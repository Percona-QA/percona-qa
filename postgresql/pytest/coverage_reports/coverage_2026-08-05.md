### Headline

1. **OS-aware install defaults** — scripts and pytest default `INSTALL_DIR` to `/usr/lib/postgresql/N` (Debian) or `/usr/pgsql-N` (RHEL) via shared helpers; `setup_test_env.sh --install-pkgs` works on both families.
2. **PITR triad harness fixes** — restore dir `chmod 0700`, exclusive LSN for DROP/TRUNCATE cuts, negative restores assert via logs / expected pgBackRest exits, `target-action=shutdown` verified without a second start that reapplied WAL.
3. **PG-2609 regressions** — sibling (and relative sibling) `pg_wal` + decrypt wrapper must archive and backup **without** segment-size mismatch; nested-under-PGDATA links must not TDE-mismatch (pgBackRest `[070]` alone is OK).

## 2. PITR harness hardening (no new scenario names)

Same modules as 2026-07-29 (`test_pitr.py` 7 · `test_pg_basebackup.py` 25 · pgBackRest PITR classes). Behavioural fixes:

| Area | Change |
|---|---|
| Restore permissions | `chmod 0700` on restore PGDATA (avoids `invalid permissions`) |
| Exclusive LSN | Capture LSN **before** DROP/TRUNCATE mark so inclusive replay does not keep the bad state |
| Negative starts | `allow_start_failure` + log assertions when cluster does not become ready |
| pgBackRest negatives | Expected exits 75 / 55 treated as pass |
| Shutdown PITR | Verify shutdown stop; data checked via separate promote-path restore |
| WAL sender GUC | Restore / WSE params keep `max_wal_senders` aligned with primary |
| Upgrade checksums | `test_upgrade_checksums_off_to_on` uses `--no-data-checksums` on PG 18+ old cluster |
